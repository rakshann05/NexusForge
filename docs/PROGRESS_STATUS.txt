MILESTONE STATUS
- v0.3.1 — Foundation Correctness & Security Hardening — COMPLETE

v0.3.1 CHANGES
- Added committed Prisma migration history (prisma/migrations); the schema is now
  reproducible on a clean database via `prisma migrate deploy`.
- Added an idempotent seed (prisma/seed.ts): 4 system roles, 18 permissions, and
  their grants. Optional DEV_SEED_USER_* creates a local-only user (never in prod).
- Added fail-fast environment validation via ConfigModule (env.validation.ts):
  validates DATABASE_URL, JWT_ACCESS_SECRET, JWT_REFRESH_SECRET, NODE_ENV,
  API_PORT, CORS_ORIGIN, REDIS_URL, NEXT_PUBLIC_API_URL; enforces >=32-char secrets
  and rejects placeholder/reused secrets in production. Secrets never logged.
- Replaced bcrypt refresh-token hashing (72-byte truncation risk) with full-length
  SHA-256 + constant-time comparison. bcrypt retained for passwords.
- Added refresh-token reuse detection: replay of a rotated/revoked token revokes the
  affected session family, writes identity.refresh_reuse_detected, and rejects.
- Added stricter throttling on login/register (10/60s) atop the global 100/60s limit;
  no permanent lockout.
- Wired real ESLint (flat config) into the lint scripts alongside type checking.
- Updated CI to provision a PostgreSQL service and run generate -> migrate deploy ->
  seed -> lint -> test -> build.
- Expanded tests: env validation, refresh-token hashing, rotation, revoked-token
  rejection, reuse detection, and permission-guard behavior (22 API tests).

MAJOR DECISIONS
- npm workspaces keep the initial monorepo simple and free to run.
- PostgreSQL + Prisma is the source of truth; SQLite is not used as a production substitute.
- AI is opt-in and provider-agnostic; AI_PROVIDER=none is a supported default.
- Local filesystem storage will sit behind an adapter before object storage is introduced.

DEPENDENCIES / BLOCKERS
- No paid service is required. Node 22+, npm, Docker, and PostgreSQL are needed locally.
- Full local validation is passing: Prisma client generation, TypeScript checks, production builds, tests, and Docker Compose parsing.
- CI uses Node 22 and `npm ci` with lifecycle scripts enabled so native dependencies, including bcrypt, install correctly before tests run.
- Password-reset delivery is intentionally UI-only until a configurable mail provider is added; core authentication does not require a paid provider.
