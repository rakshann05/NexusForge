v0.4.1 CHANGES
- Fixed passwordHash exposure in register/login/refresh responses: the publicUser
  serializer was an identity function returning the full Prisma row. Replaced it with
  toPublicUser (exported), an explicit field-picker emitting only the 9 safe user fields.
- /auth/me, /auth/sessions, /auth/roles were already safe (explicit select); refreshToken
  remains cookie-only (stripped from response bodies). No architecture/hashing changes.
- Added regression tests: toPublicUser strips passwordHash/roles/timestamps; a real
  issueTokens path (via refresh) returns a sanitized user with accessToken/sessionId.
  Live scan verified no passwordHash/tokenHash/refreshToken/secret in any auth response.

v0.4.0 CHANGES
- Added Organization.description (VARCHAR(500)) via migration add_organization_description
  (additive, nullable, preserves data). Idempotent seed unchanged.
- Org-scoped RBAC (apps/api/src/organizations/org-access.ts): OrgAccessGuard resolves the
  caller's OrganizationMember for :organizationId (404 for non-members -> tenant isolation),
  attaches it, and checks @OrgPermissions against a role->permission map reusing the seed's
  organization:read / organization:update / organization:manage_members naming. Reuses the
  existing JWT auth, CurrentUser, Prisma models, and audit logging (no second auth system).
- Organizations API (organizations.controller.ts / organizations.service.ts):
  GET/POST /organizations, GET/PATCH /organizations/:id,
  GET/POST /organizations/:id/members, PATCH .../members/:userId/role,
  DELETE .../members/:userId. Safe representations only (no passwordHash/tokens/sessions).
- Owner-safety invariants: creator becomes OWNER; org always keeps >=1 owner (last-owner
  demote/remove rejected); only OWNER may grant/revoke OWNER (blocks admin self-escalation);
  managing others needs manage_members; members may self-remove (leave); invalid roles -> 400.
- Audit events: organization.updated, organization.member_added, organization.member_role_changed,
  organization.member_removed (organization.created already existed).
- Frontend: lib/organizations.ts wrappers; sidebar org switcher; /organizations (list + create)
  and /organizations/[organizationId] (details, edit, members, role change, add/remove) pages;
  role-gated controls (UX only). Active org = URL segment (no global store).
- Tests: 14 backend org tests (guard incl. cross-tenant isolation + service invariants),
  7 frontend wrapper tests. Full suite: 63 tests (36 API + 27 web). Backend E2E verified
  cross-tenant 404s, RBAC 403s, owner-safety, and no sensitive-field leakage.

v0.3.2 CHANGES

- Added endpoint wrappers (apps/web/lib/auth.ts) and client auth state
  (apps/web/lib/auth-context.tsx): loading/authenticated/unauthenticated, silent refresh
  on mount, login/register/logout/logout-all/updateProfile, roles from /auth/roles.
- Access token kept in memory only; refresh token stays in the API httpOnly cookie.

- Client-side route guards (apps/web/components/auth-guard.tsx): Protected redirects to
  /login; PublicOnly redirects authenticated users away from /login and /register.
- Wired real flows: login, register (with client validation), logout + logout-all,
  profile (GET/PATCH /auth/me), preferences (PATCH /auth/me), and security/sessions

v0.3.1 CHANGES

v0.3.1 CHANGES
- Added committed Prisma migration history (prisma/migrations); the schema is now
  reproducible on a clean database via `prisma migrate deploy`.
- Added an idempotent seed (prisma/seed.ts): 4 system roles, 18 permissions, and
  their grants. Optional DEV_SEED_USER_* creates a local-only user (never in prod).
- Added fail-fast environment validation via ConfigModule (env.validation.ts):
  validates DATABASE_URL, JWT_ACCESS_SECRET, JWT_REFRESH_SECRET, NODE_ENV,
  API_PORT, CORS_ORIGIN, REDIS_URL, NEXT_PUBLIC_API_URL; enforces >=32-char secrets
  and rejects placeholder/reused secrets in production. Secrets never logged.
- Replaced bcrypt refresh-token hashing (72-byte truncation risk) with full-length
  SHA-256 + constant-time comparison. bcrypt retained for passwords.
- Added refresh-token reuse detection: replay of a rotated/revoked token revokes the
  affected session family, writes identity.refresh_reuse_detected, and rejects.
- Added stricter throttling on login/register (10/60s) atop the global 100/60s limit;
  no permanent lockout.
- Wired real ESLint (flat config) into the lint scripts alongside type checking.
- Updated CI to provision a PostgreSQL service and run generate -> migrate deploy ->
  seed -> lint -> test -> build.
- Expanded tests: env validation, refresh-token hashing, rotation, revoked-token
  rejection, reuse detection, and permission-guard behavior (22 API tests).

MAJOR DECISIONS
- npm workspaces keep the initial monorepo simple and free to run.
- PostgreSQL + Prisma is the source of truth; SQLite is not used as a production substitute.
- AI is opt-in and provider-agnostic; AI_PROVIDER=none is a supported default.
- Local filesystem storage will sit behind an adapter before object storage is introduced.

DEPENDENCIES / BLOCKERS
- No paid service is required. Node 22+, npm, Docker, and PostgreSQL are needed locally.
- Full local validation is passing: Prisma client generation, TypeScript checks, production builds, tests, and Docker Compose parsing.
- CI uses Node 22 and `npm ci` with lifecycle scripts enabled so native dependencies, including bcrypt, install correctly before tests run.
- Password-reset delivery is intentionally UI-only until a configurable mail provider is added; core authentication does not require a paid provider.
